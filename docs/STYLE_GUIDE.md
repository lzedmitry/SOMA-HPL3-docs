# Documentation style guide

- Short sentences. One term, one name (`Trigger Area`, not “trigger box” and “volume” on the same page unless the Wiki used both).
- No marketing language.
- Commands, filenames, extensions, and paths in backticks: `entry.hpc`, `.hps`, `F5`.
- Goal first, then steps, then why.
- Warnings only for real failure modes (wrong folder, missing sidecars, redlink).
- Beginner path and reference stay separate. Tutorials may omit a 40-row property table; the reference page must keep it.
- Do not restate the same concept five ways.
- If the Wiki does not document a parameter, write that. Do not guess.
- Mark editorial interpretation as editorial.
- Primary language: English. Identifiers stay untranslated.
