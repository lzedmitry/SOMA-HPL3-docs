Eine **Area** ist ein unsichtbares Quader im Level. Der originale Areas-Hub nennt Areas das Haupt-Ein-/Ausgabesystem von HPL3.

<p class="section-kicker">03 // AREAS &nbsp; REF 03.10</p>

Nutzen Sie sie, wenn etwas passieren soll, weil der Spieler (oder eine andere Entity) ein Volumen betreten hat, etwas angesehen hat, oder weil das Volumen selbst ein Effekt ist (Fog, Soundscape, Exposure).

:::caution[SOURCE STATUS: WIP]
Der originale SOMA-Areas-Hub ist als undergoing major editing markiert. Mehrere Typen sind gelistet, haben aber keinen Artikel (Redlinks). Parameter werden hier nicht erfunden.
:::

## Typischer Workflow

1. Area im Level Editor platzieren (Areas-Werkzeug).
2. Benennen. Namen einfach halten; Skripte suchen per Name.
3. Eigenschaften füllen, die der Typ tatsächlich dokumentiert (collide callbacks, attachment, look-at, typspezifische Felder).
4. Wenn Skript feuert: Callback auf die Map-`.hps` (oder eine Helper-Datei).
5. In-game testen. Wenn nichts feuert: [Trigger Area](/de/areas/trigger-area/) Collide-Callback-Notizen und [Troubleshooting](/de/debugging/).

Helper-Datei laut Trigger-Artikel: `helper_area.hps`. Eigene Helper-**Seiten** sind Redlinks; siehe [Helpers](/de/scripting/helpers/).
