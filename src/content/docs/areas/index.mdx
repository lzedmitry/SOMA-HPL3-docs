An **Area** is an invisible cuboid in the level. The original Areas hub calls Areas the main Input and Output system of HPL3 and the backbone of every level.

<p class="section-kicker">03 // AREAS &nbsp; REF 03.10</p>

Use them when something should happen because the player (or another entity) entered a volume, looked at something, or because the volume itself is an effect (fog, soundscape, exposure).

:::caution[SOURCE STATUS: WIP]
The original SOMA Areas hub is marked as undergoing major editing. Several types are listed but have no article (redlinks). Those rows are marked below. This site does not invent their parameters.
:::

## Typical workflow

1. Place the Area in the Level Editor (Areas tool).
2. Name it. Keep the name simple; scripts look it up by name.
3. Fill the properties the type actually documents (collide callbacks, attachment, look-at, type-specific fields).
4. If it fires script, put the callback on the map `.hps` (or a helper file).
5. Test in-game. If it never fires, read [Trigger Area](/areas/trigger-area/) collide-callback notes and [Troubleshooting](/debugging/).

Helper file named by the Trigger article: `helper_area.hps`. Dedicated helper **pages** are redlinks; see [Helpers](/scripting/helpers/).
